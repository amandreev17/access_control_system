# СКУД — Система контроля и управления доступом на основе динамических QR-кодов

Веб-приложение для генерации и валидации динамических QR-кодов доступа. Разработано для СКУД (систем контроля и управления доступом).

**Стек технологий:**
- **Бэкенд:** Go (Gin framework) + SQLite
- **Фронтенд:** React 17
- **Криптография:** RSA-2048 подпись с SHA-256 (TOTP-стиль)

## Как это работает

### 1. Аутентификация пользователя

Пользователь входит в систему по логину и паролю. Бэкенд проверяет учетные данные в SQLite и выдает JWT-токен (24 часа действия).

**Тестовые учетные записи:**
| Логин    | Пароль    | ФИО               | Роль    |
|----------|-----------|-------------------|---------|
| admin    | admin123  | Администратор     | admin   |
| user1    | user123   | Иванов Иван       | user    |
| user2    | user123   | Петров Петр       | user    |

### 2. Генерация динамического QR-кода

После входа пользователь видит QR-код, который автоматически обновляется каждые **10 секунд**:

1. **Формирует данные:** `user_id:full_name:role:timestamp_interval:expiry_timestamp`
   - `timestamp_interval` — текущее время, округленное до 10-секундного интервала (TOTP-стиль)
   - `expiry_timestamp` — время истечения (+10 секунд)
2. **Подписывает RSA-ключом:** Данные хэшируются через SHA-256, подписываются приватным RSA-ключом (2048 бит)
3. **Формирует токен:** `данные|RSA-подпись`
4. **Сохраняет в БД:** QR-код записывается в таблицу `qr_codes`
5. **Отображает пользователю:** QR-код генерируется из полного токена и автоматически обновляется каждые 10 секунд

### 3. Валидация QR-кода (СКУД)

Считыватель отправляет токен на эндпоинт `/api/validate-qr`. Сервер:

1. **Проверяет RSA-подпись** — если подпись недействительна, доступ запрещен (QR-код подделан)
2. **Проверяет срок действия** — если QR-код истек (>10 секунд), доступ запрещен
3. **Проверяет повторное использование** — если QR-код уже был использован в этом интервале, доступ запрещен
4. **Проверяет существование пользователя** — если пользователь удален, доступ запрещен
5. **Логирует событие** — запись в таблицу `access_logs`

### 4. Управление пользователями

Администратор может создавать и удалять пользователей через веб-интерфейс (кнопка **«Управление»**) или через API.

### 5. База данных SQLite

Три таблицы:

- **users** — пользователи системы (логин, хэш пароля bcrypt, ФИО, роль)
- **qr_codes** — история сгенерированных QR-кодов (токен, время выпуска/истечения, флаг использования)
- **access_logs** — журнал попыток доступа (токен, пользователь, статус, сообщение, время сканирования)

## API эндпоинты

| Метод | Путь                | Аутентификация | Описание                          |
|-------|---------------------|----------------|-----------------------------------|
| POST  | `/api/login`        | Нет            | Вход в систему                    |
| GET   | `/api/public-key`   | Нет            | Публичный RSA-ключ для считывателя|
| POST  | `/api/validate-qr`  | Нет            | Валидация QR-кода (СКУД)          |
| GET   | `/api/profile`      | JWT            | Профиль пользователя              |
| POST  | `/api/generate-qr`  | JWT            | Генерация нового QR-кода          |
| GET   | `/api/access-logs`  | JWT            | Журнал попыток доступа            |
| GET   | `/api/users`        | JWT + admin    | Список пользователей              |
| POST  | `/api/users`        | JWT + admin    | Создать пользователя              |
| DELETE| `/api/users/:id`    | JWT + admin    | Удалить пользователя              |

## Запуск проекта

### Предварительные требования

- **Go** 1.21+
- **Node.js** 16+ (npm)

### 1. Запуск бэкенда (Go-сервер)

```bash
cd backend
go mod tidy
go run main.go
```

Сервер запустится на порту **8080**.

При первом запуске:
- Генерируется RSA-пара ключей (сохраняется в `backend/keys/`)
- Создается база данных SQLite (`backend/data/skud.db`) с тестовыми пользователями

**Сборка бинарника:**
```bash
cd backend
go build -o skud-server .
./skud-server
```

### 2. Запуск фронтенда (React)

**Для разработки:**
```bash
npm install --legacy-peer-deps
npm start
```

Фронтенд запустится на порту **3000**.

**Для Android по локальной сети (PWA):**
```bash
npm run build
npm run serve
```

Скрипт `serve.sh` автоматически:
- Определит IP вашего Mac (например, `192.168.0.126`)
- Запустит сервер на порту 3000
- Покажет адрес для Android: `http://192.168.0.126:3000`

**Автодетекция API:** фронтенд автоматически определяет IP-адрес сервера, с которого он открыт, и обращается к API на `http://<этот-же-IP>:8080/api`. Это значит, что на Android ничего настраивать не нужно — просто откройте сайт по IP Mac.

### 3. Открытие в браузере

Перейдите на [http://localhost:3000](http://localhost:3000) — откроется страница входа.

## Установка на Android как PWA (без домена)

Самый простой способ использовать приложение на Android — установить как PWA ( Progressive Web App). **Не нужен домен, не нужен HTTPS, работает по локальному IP.**

### Предварительные требования

- Mac и Android подключены к одной Wi-Fi сети
- Бэкенд запущен на порту 8080
- Файрвол разрешает входящие соединения (обычно по умолчанию разрешены)

### Шаг 1: Соберите фронтенд

```bash
npm run build
```

После сборки в папке `build/` будут все нужные файлы.

### Шаг 2: Запустите статический сервер

```bash
npm run serve
```

Или вручную:
```bash
npx serve -s build -l 3000
```

Скрипт `serve.sh` автоматически определит ваш локальный IP и покажет адрес для открытия на Android.

### Шаг 3: Откройте на Android

1. На Android откройте **Chrome**
2. Перейдите по адресу, который показал сервер, например:
   ```
   http://192.168.1.42:3000
   ```
3. Дождитесь загрузки страницы входа
4. Нажмите меню Chrome (три точки) → **«Добавить на главный экран»** (Add to Home screen)
5. Подтвердите добавление

Приложение установится как обычное приложение на главном экране Android. При запуске оно будет открываться в полноэкранном режиме (без адресной строки), как нативное приложение.

### Как узнать IP вашего Mac

```bash
ipconfig getifaddr en0
```

Пример вывода: `192.168.1.42`

### Если приложение не открывается

1. Убедитесь, что Mac и Android в одной Wi-Fi сети
2. Проверьте, что бэкенд запущен на порту 8080:
   ```bash
   curl http://localhost:8080/api/public-key
   ```
3. Проверьте файрвол macOS: **System Settings → Network → Firewall → Turn On** (должен быть включен)
4. Убедитесь, что порт 3000 не заблокирован

### Обновление приложения

После изменений в коде:
1. Остановите сервер (`Ctrl+C`)
2. Выполните `npm run build`
3. Запустите `npm run serve` снова
4. На Android обновите страницу в Chrome

PWA автоматически обновит кэш при следующем открытии.

### Как пользоваться

**Тестовые учетные данные:**
- **admin** / admin123 (администратор)
- **user1** / user123 (пользователь)
- **user2** / user123 (пользователь)

**Функции:**
- QR-код обновляется каждые 10 секунд
- Администратор может управлять пользователями (кнопка "Управление")
- СКУД считыватель валидирует QR через API

Токен QR-кода имеет формат:

```
user_id:full_name:role:timestamp_interval:expiry_timestamp|base64_rsa_signature
```

Пример:
```
1:Администратор:admin:1784271600:1784271610|iEwDvivql04CqogEBEUdK7NcY1...
```

Считыватель должен отправить этот токен на `POST /api/validate-qr` для проверки доступа.

## Безопасность

- Пароли хранятся в виде bcrypt-хэшей
- JWT-токены с ограниченным сроком действия (24 часа)
- RSA-2048 подпись данных QR-кода (предотвращает подделку)
- QR-код действителен только 10 секунд (TOTP-стиль)
- QR-код нельзя использовать повторно в течение интервала
- CORS настроен для работы с произвольных источников
